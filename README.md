# AI Code Review

本项目采用 [MIT 开源协议](LICENSE)，允许商业使用、修改与分发，须保留版权和许可声明；软件不提供担保。

给 Gitea 仓库接入 AI 代码审查：推送后按项目文档和 Skill 规范检查代码及文件变更，输出中文报告。有问题、建议或待确认事项都会发钉钉。默认不阻断 CI，可按仓库开启。

## 文件筛选超时重试

文件筛选阶段的OpenAI请求超时后最多重试5次（首次加重试共6次，每次120秒超时），退避等待1、2、4、8、8秒；中途成功立即停止，全部超时再尝试Claude。认证失败、无效返回不做这类超时重试，直接走原备用逻辑。报告记录每次超时和最终使用的服务。规划启动预算调整为900秒，预算控制新组和备用请求启动；已启动组的OpenAI重试链不会被预算中断，实际时长可能超过启动预算。此改动仅针对文件筛选，不改变详细审查或钉钉重试策略。

## 审查器仓库来源

新模板默认从 `https://github.com/ayflying/ai-code-review.git` 拉取工具。可在 Actions Variables 设置 `AI_REVIEW_TOOL_REPOSITORY` 为其他不含凭据的HTTPS仓库地址，例如自建Gitea镜像；拉取失败时自动尝试默认GitHub，保持同一个 `AI_REVIEW_TOOL_REF`，不静默换版本。两边都失败时明确记录工具未加载。非法地址直接拒绝，不尝试发送凭据。

公开仓库匿名读取；私有镜像可配置 `AI_REVIEW_TOOL_READ_TOKEN` Secret。仅配置仓库与当前Gitea同源时允许使用任务令牌，回退GitHub不携带镜像专用令牌，也不跟随HTTP重定向。此来源选择发生在工具拉取之前，旧工作流需一次性更新拉取步骤和变量接线，不能靠工具自动更新获得。

注意：GitHub仓库已创建，但本机此前推送因GitHub认证失败，尚未核验GitHub已有工具代码；默认源投入使用前需完成GitHub同步。现有Gitea接入不自动替换。

## 1. 添加工作流

把本仓库的 [examples/ai-code-review.yml](examples/ai-code-review.yml) 文件复制到需要审查的项目中，保存为：

```text
你的项目/.gitea/workflows/ai-code-review.yml
```

如果 `.gitea/workflows` 目录不存在，先创建。源文件请使用本仓库 main 分支的版本。

只需复制一次，不用复制 Python 脚本。每次 CI 自动拉取本工具仓库 main 的最新代码，在业务仓库中执行；后续升级不需要修改业务工作流。旧版固定标签的工作流需要最后替换一次。

## 2. 配置密钥和模型

在**业务仓库或其所属组织**的 Actions 设置中配置以下内容；只配置到工具仓库不会生效。

**Secrets（密钥）**

| 名称 | 是否必填 | 用途 |
| --- | --- | --- |
| `AI_REVIEW_OPENAI_API_KEY` | 必填 | 主模型密钥；为空时跳过全部审查和通知 |
| `AI_REVIEW_TOOL_READ_TOKEN` | 按需 | 读取本工具仓库的最小只读令牌；任务自带令牌能跨库读取时可不配 |
| `AI_REVIEW_CLAUDE_API_KEY` | 可选 | 主模型失败后使用的备用密钥 |
| `AI_REVIEW_DINGTALK_WEBHOOK` | 可选 | 钉钉机器人的完整 Webhook 地址 |

**Variables（普通变量）**

| 名称 | 是否必填 | 用途 |
| --- | --- | --- |
| `AI_REVIEW_OPENAI_MODEL` | 必填 | 账号可用的准确模型 ID |
| `AI_REVIEW_OPENAI_BASE_URL` | 可选 | 默认 `https://api.openai.com/v1`，不要加 `/responses` |
| `AI_REVIEW_CLAUDE_MODEL` | 使用备用时必填 | 备用模型 ID |
| `AI_REVIEW_CLAUDE_BASE_URL` | 可选 | 默认 `https://api.anthropic.com/v1`，不要加 `/messages` |

密钥、Webhook 和 Git 令牌只能放 Secrets，不能写进代码、文档或普通变量。runner 需预装 Python 3.10+、Bash、Git，并能访问工具仓库和模型服务；不需要安装业务依赖。

## 3. 可选配置（后台修改，不用改工作流）

在业务仓库或组织的 Actions Variables 配置；不配置就使用默认值：

| 名称 | 默认值 | 说明 |
| --- | --- | --- |
| `AI_REVIEW_BLOCK_ON_RISK` | `false` | `true` 时明确代码风险/规范问题让 CI 失败；建议和待确认不阻断 |
| `AI_REVIEW_NOTIFY_LEVEL` | `all` | 通知门槛：all 包含问题/建议/待确认；low、medium、high 仅明确问题达到对应级别才通知；不影响阻断 |
| `AI_REVIEW_DINGTALK_KEYWORD` | `git` | 与机器人的安全关键词一致 |
| `AI_REVIEW_TOOL_REF` | `main` | 自动使用工具最新代码；需要回退/锁定时改为不可变发布标签 |
| `AI_REVIEW_MAX_BATCHES` | `20` | 最大审查批数，允许1–200 |
| `AI_REVIEW_MAX_FILES` | `300` | 最大考虑文件数，允许1–5000 |
| `AI_REVIEW_BATCH_BYTES` | `100000` | 每批差异字节数，默认100KB，允许1000–1000000 |
| `AI_REVIEW_INPUT_BYTES` | `160000` | 单次总输入字节预算，含提示和规范，允许10000–2000000；不是token数 |
| `AI_REVIEW_OPTIONS_JSON` | 空 | 非密钥扩展参数，后续新参数通过此入口传给工具 |

机器人默认使用环境已配置的 `AI_REVIEW_DINGTALK_WEBHOOK` Secret；更换机器人就在后台更新该 Secret，未配置则不通知。禁止明文地址；当前不支持加签机器人。

扩展配置示例：`{"block_on_risk":true,"dingtalk_keyword":"gitea"}`。目前支持 `block_on_risk`、`notify_level`、`dingtalk_keyword`、`openai_model`、`openai_base_url`、`claude_model`、`claude_base_url`、`max_batches`、`max_files`、`batch_bytes`、`input_bytes`，显式值优先于单项变量；未知字段会报配置错误。不要放密钥。

默认跟随 main 意味着工具更新会直接影响后续 CI，必须限制工具仓库写权限。日志记录实际运行 SHA；需要复现时先锁定发布标签。旧标签必须支持稳定入口 v1（含 `--policy`），例如 v1.2.0 及更早版本不支持该入口，不能直接回退到这些标签。

## 4. 推送并查看结果

提交工作流后推送分支，或在 Actions 中手动运行 **AI Code Review**。

在 **生成中文风险报告** 步骤查看报告：

- 主模型优先，调用失败或报告格式无效时才使用备用模型。
- 专用 AI 审查接入文件 `.gitea/workflows/ai-code-review.yml`（或 `.yaml`）不送模型审查，避免内部协议反复成为业务待确认项；其他业务 CI/发布文件仍审查。只改接入文件时不调用模型、不发送业务审查通知。
- 审查围绕业务项目，不评价 AI 审查工具的自动更新/版本锁定、模型/通知/分批等运维选择，也不因缺少外部审查器源码提出接口确认计划。有具体证据的秘密泄露、越权或业务构建发布破坏仍报告；不因引用 main 就单独提出工具锁定建议。
- 报告分为明确问题、改进建议、待确认事项；默认 `all` 下任一有内容都会发钉钉。设为 `low`/`medium`/`high` 后，明确问题（含规范问题）达到门槛才发送；纯建议/待确认不触发。触发后消息与产物仍包含全部结果。全部为空或模型审查失败不发送。
- 通知门槛与 CI 阻断独立：例如门槛 `high`、阻断 `true` 时，low 问题仍可让 CI 失败但不发通知。旧模板可用 `AI_REVIEW_OPTIONS_JSON={"notify_level":"medium"}`，无须为此更换工作流。非法级别会明确报配置异常，不静默放宽。
- 钉钉只发简短摘要：仓库与短提交号、问题/建议/待确认数量、最多两条问题影响，以及一个报告产物在线预览链接；不复制覆盖日志和整份报告，不额外调用模型总结。新模板先上传产物再通知；直接打开 HTML 报告在线预览（实例须支持产物预览），另保留 Markdown 下载，问题详情在前、覆盖说明在后。通知展示提交说明及重点影响，不列源码路径和行号。链接固定本次产物，保留30天，私有仓库需登录及读取权限；上传失败不发无效链接。已接入的旧模板需要一次性补充上传和通知步骤，直接复制最新版模板即可。
- 钉钉通知成功以机器人返回 `errcode=0` 为准，不能只看 HTTP 成功或 CI 绿色。
- 不要通过引入漏洞或伪造风险测试通知；真实测试消息需明确授权并标注测试用途。

需要阻止合并时，还要在分支保护中将此工作流设为必需检查；它不能撤销已发生的推送。

## 通知优先级与分条

模型根据影响大小、触发难易和影响范围，为每个明确问题给出0～100整数危险度评分及简短中文理由。详细报告与钉钉均按实际分数降序排列，同分维持原顺序；通知门槛仍使用severity，风险阻断仍按明确问题判断，不随分数改变。此分数是AI修复优先级估计，不是CVSS或已验证漏洞。旧模型未返回评分时暂用high=90、medium=60、low=30并明确标记“等级参考”，不冒充独立评分。钉钉只发一条，最多展示严重程度最高的3个问题，并提示剩余数量；保留仓库、关键词和报告链接，不再拆条。拒收或网络异常不自动重复发送。完整报告不截断问题，所有明确问题统一放在同一章节，不因每40条分组重复章节。

## 同次 CI 的文件规划与共享上下文

先加载项目规范，由 AI 根据变更路径、差异大小和少量样本决定审查文件，之后才按选中文件分批。明确的生成标记、第三方依赖或构建产物证据才允许跳过；不确定、缺失/重复/未知路径或调用失败均保守保留。每组先 OpenAI，失败或格式无效才用 Claude，最多20组、120秒新请求启动预算；不能以注释“不要审查”为依据。基础敏感路径、二进制等排除先于规划，文件数和20MB候选差异硬限仍保留。

规划摘要与审查关注点仅在本次进程内共用（最多6000字节，小输入配置还会缩减），后续每批仍加载对应规范原文，摘要不能作为规范引用证据；不累计完整对话，不使用服务端会话，不跨CI持久化源码。规划增加模型调用；文件清单本身按输入预算分组。HTML报告折叠说明中保留逐文件决定、理由、统计、规划依据覆盖情况和共享计划；未进入候选预算的文件仍单独说明覆盖不完整。触发通知后钉钉继续只展示短摘要和报告链接。

## 能检查什么

检查本次变更中的安全、权限、逻辑、数据、并发、兼容性和稳定性风险，**不是全仓库扫描，也不能替代测试和人工审查**。

### 项目规范放在哪里

把规范提交到被审项目，CI 自动读取，不需要额外配置。文件清单按规范路径查询，不再一次枚举全仓库；大规范目录超限时拆分目录继续读取，局部失败保留其他成功加载的规范。文档内容仍遵守单文件、总输入预算及敏感信息保护限制，并不承诺无限加载：

| 位置 | 内容 |
| --- | --- |
| 根目录 `README.md`、`AGENTS.md`、`CONTRIBUTING.md` | 项目说明和开发要求 |
| 变更文件所在目录及其上级的 `AGENTS.md`、`README.md` | 模块专用规则 |
| `.agents/skills/`、`.claude/skills/`、`.skills/`、`skills/` 下的 `SKILL.md` | 项目自带 Skill 说明 |
| `docs/` 下的 Markdown 文档 | 补充规范和设计说明 |

明确违规会附上规范路径、行号和原文；不确定或规范冲突则列为待确认。只读取被审提交中的文件，不执行 Skill 脚本，也不递归读取 Skill 引用的其他文件。

每批按表格顺序优先加载，最多尝试 20 份文档、每份 12KB，编号后的规范上下文最多 60KB（还受本批输入预算约束）；仅支持 UTF-8 普通文件，超限整份跳过。日志列出已加载、缺失或跳过的文档，不能保证覆盖全部规范。规范和代码会一起发送给模型。

### 修改太多时怎么办

自动分批，不需要改工作流：优先按文件组合，每批差异默认最多 100KB，可通过 `AI_REVIEW_BATCH_BYTES` 修改；大文件按差异块拆分，单块过大再按行拆分，保留文件名和原始行号。每批独立附带涉及模块的规范，主模型失败后只对该批尝试备用模型。

最后本地合并结果、去除完全重复的条目，只发送一次钉钉；任一批发现明确问题仍保留风险状态。失败或未审完的批次会明确标注，不能把部分完成当作整个提交安全。

默认最多考虑 300 个文件、20 批，均可在 CI 顶部或后台 Variables 修改；旧工作流可通过 `AI_REVIEW_OPTIONS_JSON` 设置相同参数，无需换文件。总差异预算为“批次数 × 每批大小”，最高20MB；单文件 Git 差异读取上限2MB。15分钟后不再启动新批次（在途请求可能继续耗时），调大批数不等于必定审完。

单次系统提示、差异、规范和协议预留合计输入预算默认160KB，可通过 `AI_REVIEW_INPUT_BYTES` 修改。每批差异会自动限制在总输入预算减10KB以内，给提示与规范留空间。这里是 UTF-8 字节，不是模型的 token；例如200K token上下文不能直接当200KB，还需要留输出额度。无法保证所有模型都不超限。超限、极端长行和未完成项会标明；调大额度会增加费用和耗时，跨批关联问题仍可能漏报。

## 使用前注意

- 代码会发送给主、备模型服务，启用前需确认允许外发；敏感文件过滤不保证源码没有密钥。
- 只允许可信人员修改和触发带 Secrets 的工作流；固定工具版本不能隔离恶意工作流。
- 只监听分支 push 和手动运行，不处理 PR 或 tag。手动运行、新分支只审最近一次提交。
- 差异有大小限制，跨文件上下文有限；排除、超限或调用失败会标明覆盖不完整，不代表安全。
- 不执行业务代码、不自动修复或合并。钉钉消息不含原始 diff，重跑可能重复通知。

开发与发布规则见 [开发指南](AGENTS.md)，版本和真实验证状态见 [交接记录](docs/handoff.md)。
